## 一、核心結論

**加 CLI 與減 CLI 的成本不對稱。**

| 動作 | 流程要不要改 | 主要成本 |
|---|---|---|
| **加**一個 CLI（保留現有） | ❌ 不用 | 補五項 CLI 專屬細節；因無抽象層，需改 3 份文件約 10 處 |
| **減** agy | ✅ **要改** | Level 1 會變成零 reviewer（見 §4.3） |
| **減** copilot | ✅ **大改** | 三個角色同時失去引擎，且 **developer 白名單整份失效** |
| 減 claude-reviewer | ⛔ **禁止** | §2 紅線：developer 與探索都外包後，它是唯一獨立驗證環節 |

v5.0 的角色按**功能**定義（explorer／developer／reviewer），不按 CLI 定義。所以加 CLI 是**多一個引擎選項**，不是多一個角色——review 流程本身完全不受影響。

## 二、v5.0 的哪些部分與 CLI 耦合

### 2.1 完全 CLI-agnostic（加減 CLI 都不用碰）

- MANIFEST 四段（含契約面清單）
- Review Levels ／ Effort 二維
- findings schema、路徑正規化
- `DONE` 機械驗證、Conflict Handling
- developer A/B 准入 gate（機制本身）
- Bias Mitigation、Budget Pressure、reviewer 不作預算調節閥

### 2.2 每個 CLI 必須各自填的五項

| # | 項目 | 為何無法共用 |
|---|---|---|
| 1 | **權限與呼叫旗標** | copilot 用 `--allow-all-tools`；agy 用 `--dangerously-skip-permissions`——**完全不同**，且 agy 缺旗標時會「假成功」 |
| 2 | **輸出解析** | 兩者 stdout 都不乾淨，但**髒法不同**：copilot 把敘述混在前段、JSON 在尾端；agy 失敗時在 JSON 前加一行診斷文字 |
| 3 | **模型命名慣例** | copilot 用點（`claude-haiku-4.5`）、agy slug 用連字號（`claude-sonnet-4-6`）。第三個 CLI 可能是第三種 |
| 4 | **錯誤偵測樣式** | 各家錯誤訊息格式不同；agy 另需「`SUCCESS` 但 `structured_output` 為空」的假成功偵測 |
| 5 | **`resolve_model` 分支** | tier → 實際模型的解析邏輯 |

### 2.3 🔴 結構性負債：沒有抽象層

實測 v5.0 文件中的提及次數：

| CLI | SKILL.md | cli-invocation-ref | agents-prompts | 合計 |
|---|---|---|---|---|
| copilot | 25 | 24 | 13 | **62** |
| agy | 15 | 31 | 19 | **65** |

這些細節是**內嵌在每個角色協定裡**的。加第四個 CLI 等於改 3 份文件約 10 處，且容易漏改其中一處而不自知——**這正是「靜默失效」最容易發生的形狀**。

## 三、方案 A：CLI Adapter 表（無論擴充與否都建議做）

把 §2.2 的五項抽成一張表，角色協定改為引用表格欄位而非硬寫指令。

### 3.1 表格結構

```markdown
| 欄位 | copilot | agy | {新 CLI} |
|---|---|---|---|
| 權限旗標 | `--allow-all-tools` | `--dangerously-skip-permissions` | ? |
| 目錄授權 | `--add-dir <dir>` | `--add-dir <dir>` | ? |
| 成本上限 | `--max-ai-credits <n>`（最小 30） | 無 | ? |
| 精簡輸出 | `-s` | 無（用 `--output-format json`） | ? |
| 結構化輸出 | prompt 約束 JSON | `--json-schema <file>` | ? |
| effort | `--effort low\|…\|max` | `--effort low\|medium\|high` | ? |
| stdout 乾淨度 | ❌ 敘述在前、JSON 在尾端 | ❌ 失敗時前面加診斷行 | ? |
| 解析取法 | `grep -o '{"findings".*}' \| tail -1` | `.structured_output`（非 `.response`） | ? |
| 模型命名 | 點（`claude-haiku-4.5`） | 連字號（`claude-sonnet-4-6`） | ? |
| 無效模型行為 | 明確報錯 | 明確報錯（v1.1.8 起） | ? |
| 假成功徵兆 | 無已知 | `SUCCESS` 但 `structured_output` 空 | ? |
| 模型枚舉 | 無子命令（互動模式 `/model`） | `agy models`（⚠️ 須接管線，重導向會 hang） | ? |
```

### 3.2 效益

| | 現況 | 加了 adapter 表 |
|---|---|---|
| 加一個 CLI | 改 3 份文件約 10 處 | **加 1 列** |
| 漏改風險 | 高（且漏改是靜默的） | 低（空欄位即為 TODO，一目了然） |
| 換主引擎 | 需通篇重寫 | 換一列 + 重跑 A/B |

### 3.3 建議

**無論要不要擴充都該做。** 它把「靜默漏改」轉成「表格有空格」，符合 v5.0 一路以來的核心教訓：**讓失敗發出聲音**。

## 四、情境評估

> ⚠️ 本節除已標「實測」者外，**codex／opencode 的能力皆未驗證**。標示 `?` 者一律需經 §五探測。

### 4.1 情境一：保留 copilot，額外加 codex

**評估：不建議。**

codex 是 GPT／OpenAI 家族，而 copilot 已提供 `gpt-5.6-terra`／`gpt-5.6-luna`／`gpt-5.4`／`gpt-5.3-codex`／`gpt-5-mini`（**實測確認**）。加它幾乎買不到模型家族多樣性，唯一價值是**額度分散**——而那已是 agy 的職責。

成本（五項細節 + 3 份文件改動）實在，收益薄。

### 4.2 情境二：保留 copilot，額外加 opencode

**評估：取決於是否想淘汰 agy。**

未採納的 `archive/重構建議-v4.4-opencode遷移.md` 記載其核心賣點是**免費模型池**（`opencode/*` 完全免費）與統一介面 `opencode run -m {provider/model}`。這與 agy 佔**同一個格子**（免費額度）。

- 保留 agy → opencode 冗餘
- 想淘汰 agy → opencode 可接手免費額度那格

⚠️ v4.4 提到 opencode 是「統一存取 OpenCode 原生模型**與 GitHub Copilot 模型**」——後半段可能仍需 Copilot 訂閱，**不可當成免費午餐**，需探測確認。

### 4.3 情境三：減掉 agy

🔴 **會踩到具體斷點，必須改流程。**

```
Level 1 — Quick scan (--quick) : gemini-reviewer only
```

`gemini-reviewer` 就是 agy。**減掉它，Level 1 變成零 reviewer。**

必要調整：
1. Level 1 改指向某個 copilot reviewer（並重新設定其 tier／effort）
2. 接受失去 agy 僅存的兩項價值——**跨供應商分散額度**（三 reviewer 全走 copilot 會共用同一 Credit 池，違反 §2 紅線列的天然優勢）與**免費額度**（官方費率表確認 copilot **無任何免費模型**）

### 4.4 🔴 情境四：退訂 copilot，改訂 codex 或 opencode

**這是影響最大的情境。** copilot 一走，**三個角色同時失去引擎**：

| 角色 | 現況引擎 |
|---|---|
| explorer | copilot（常態外包） |
| developer | copilot（**預設**） |
| copilot-reviewer | copilot |

#### 🔴 硬阻擋：developer 白名單整份失效

```
DEV_ALLOWED="gpt-5.4-mini claude-sonnet-5 gpt-5.3-codex gpt-5.6-terra gpt-5.4"
```

**這五個全是 copilot 的 slug。** 退訂 copilot → 白名單歸零 → 依 v5.0 自己的 `assert_dev_model` gate，**沒有任何模型有資格擔任 developer**，直到重跑 A/B 准入。

這不是文件問題：phase2／phase3 那三輪 A/B 是實際花 credits 跑出來的，換 CLI 等於結論全部作廢。**這是換 CLI 最實在的成本，遠大於改文件。**

#### 候選比較

| | codex | opencode |
|---|---|---|
| 本機版本 | `codex-cli 0.146.0`（已安裝） | `1.18.9`（已安裝） |
| 模型家族 | 僅 OpenAI／GPT | 多供應商（設計目標） |
| 結構上像誰 | 單一家族引擎 | **最接近 copilot 的「一個 CLI 多家族」** |
| 免費額度 | ? | v4.4 記載 `opencode/*` 完全免費（待驗） |
| 對多樣性的影響 | 需靠 codex(GPT) + agy(Gemini/Claude/GPT-OSS) + native(Claude) 拼回三家族——即 v4.x 形狀 | 可能單一 CLI 涵蓋多家族，**有機會從三 CLI 收斂到兩個**（opencode + native） |

#### 連帶失去的能力

退訂 copilot 同時失去 `--max-ai-credits`——那是「空跑燒錢」**唯一的硬防護**（實測確認最小值 30）。替代 CLI 若無等價機制，需接受該風險或自建上限。

### 4.5 情境五：三 reviewer 全走同一個 CLI

E3 實測發現 copilot 單一 CLI 已涵蓋 **GPT／Claude／Gemini／Grok／Kimi 五個家族**。因此「三 reviewer 來自三個 CLI」可改為「**三 reviewer 來自同一 CLI、指定不同家族**」。

| | 好處 | 代價 |
|---|---|---|
| 收斂到單一 CLI | 五項細節只需維護一份，複雜度大降 | 三 reviewer 共用同一 Credit 池，**失去跨供應商分散**（§2 紅線） |

這是真實取捨，非明顯對錯。若採納，§2 紅線需修訂並記錄理由。

## 五、探測計畫（採納前必跑）

⚠️ **不可先決定再驗證。** v5.0 期間有四項「寫進文件才被實測推翻」的主張，成因都是先下結論。

對每個候選 CLI 跑以下探測（多數是 `--help` 與零成本查詢）：

| # | 探測 | 為何關鍵 |
|---|---|---|
| P1 | 有無 `--add-dir` 等價物 | **v5.0 核心設計就是傳路徑**；沒有它整個傳遞層要重做 |
| P2 | 有無成本上限旗標 | 取代 `--max-ai-credits` 的空跑防護 |
| P3 | stdout 乾不乾淨（單輪 vs 多步驟工具呼叫） | 現有兩個 CLI **都不乾淨**，第三個沒理由假設乾淨。**必須在多步驟負載下測**（E6-bis 的教訓：單點驗證不可外推） |
| P4 | headless 權限模型 | agy 需 `--dangerously-skip-permissions`，缺它會**假成功** |
| P5 | 結構化輸出／JSON schema 支援 | findings 解析依賴 |
| P6 | 模型命名慣例與枚舉方式 | 第三種慣例；且 `agy models` 有「重導向會 hang」的坑 |
| P7 | 無效模型的行為 | 是明確報錯還是靜默降級？後者必須自建防護 |

**輸出**：填入 §3.1 的 adapter 表，空欄位即為未知，不得以推測填補。

## 六、遷移步驟

| # | 動作 | 前置 |
|---|---|---|
| 1 | 建立 CLI adapter 表，把現有 copilot／agy 兩列填滿（資料已在文件內，只是散落） | — |
| 2 | 三份角色協定改為引用 adapter 表欄位 | 1 |

**步驟 1–2 可獨立於任何擴充決策先做**，且做完之後步驟 3–6 的成本大幅下降。

## 七、風險

| 風險 | 說明 | 緩解 |
|---|---|---|
| 🔴 **A/B 結論作廢** | 換主引擎使 `DEV_ALLOWED` 歸零，三輪 A/B 的 credits 白花 | 先確認要換再換；換前把 adapter 表做好，讓重跑成本降到最低 |
| 🔴 **失去成本硬上限** | 替代 CLI 若無 `--max-ai-credits` 等價物，空跑燒錢無防護 | P2 探測；必要時自建（如超時中止 + 事後對帳） |
| **漏改某一處** | 無 adapter 表時，10 處改動漏一處且不會報錯 | 方案 A 本身即為緩解 |
| **推測填補未知** | 把 `?` 當成「大概跟 copilot 一樣」 | §五強制探測；空欄位不得推測填補 |
| **一次換太多變數** | 同時換 CLI 與調流程，出問題無法歸因 | 一次只換一個變數（A/B 方法論規則 6，實測踩過） |
