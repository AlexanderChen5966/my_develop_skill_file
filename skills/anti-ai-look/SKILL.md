# 去 AI 味檢查

這些痕跡代表**沒有經過選擇的預設值**。案子明確要這個風格時可以保留，但要寫明為什麼；否則任何一條成立就改。

## 怎麼用

1. 先確認有該專案或作品的 `DESIGN.md`。沒有就先叫 `design-md-init`，不要在沒有規格的情況下開始畫或評
2. 網頁畫面若環境已有 `impeccable` 的掃描器（`npx impeccable detect`），先跑它；這份清單補它涵蓋不到的部分：中文文案、icon 規格、和既有畫面的一致性。Flutter 畫面掃描器不適用，整份人工對照
3. 有瀏覽器工具時**實際開頁截圖**逐條看，不憑程式碼想像
4. 逐條對照下面的清單。每一條寫「成立／不成立」，成立的附位置與建議改法；不要只回「看起來還好」
5. 做 icon 時加看 [references/icon-spec.md](references/icon-spec.md)

## 清單

**視覺**
- [ ] 顏色、字型、圓角、陰影全部來自該專案 `DESIGN.md` 的 token，沒有模型預設值
- [ ] 沒有紫藍或粉紫的漸層背景、漸層文字
- [ ] 沒有用 emoji 當圖示；圖示來自專案既有的圖示庫
- [ ] 不是每個區塊都包成「白卡＋圓角＋陰影」
- [ ] 沒有「置中大標題＋副標＋兩顆按鈕＋三欄功能卡」的固定首頁版型
- [ ] 間距有節奏（相關的近、不相關的遠），不是全部等距
- [ ] 資訊密度符合使用情境（後台表格要密，不是行銷頁的大留白）

**第二層 AI 味**（模型避開紫色漸層之後的新預設，看起來有品味，更難發現）
- [ ] 不是奶油色底加赤陶色點綴
- [ ] 不是細襯線大標題配一個斜體或換色的強調字
- [ ] 不是近黑底只配一個螢光綠或朱紅
- [ ] 沒有報紙式細線密排版面
- [ ] 沒有全大寫或等寬字體的裝飾小標籤
- [ ] 01／02／03 編號只用在真的有順序的內容
- [ ] 沒有假視窗三圓點

**真實性**
- [ ] 沒有捏造的數字、客戶 logo、推薦語；沒有資料就標示「待補」

**文案**
- [ ] 沒有空泛形容詞（「強大的」「無縫的」「一站式」「賦能」）
- [ ] 按鈕寫動作（「匯出報表」），不寫「立即開始」「探索更多」
- [ ] 中文用臺灣用語，沒有翻譯腔
- [ ] 狀態訊息具體（「已匯出 128 筆」），不寫「操作成功！」

**一致性**
- [ ] 新畫面和同專案既有畫面放在一起，看不出是另一個人做的
- [ ] 元件用專案既有的，沒有另做一套

## 輸出格式

```
去 AI 味檢查：<畫面或檔案>
DESIGN.md：<路徑／沒有>
成立（要改或要說明保留理由）：
1. <條目> — <位置> → <建議>
不成立：<條目編號或「其餘全部」>
沒法判斷：<條目> — <原因，例如沒有截圖、沒有 token 可對照>
```

只列證據看得到的。沒有看到的條目寫「沒法判斷」，不要猜成「不成立」。

## 常見藉口

| 藉口 | 為什麼不成立 |
|---|---|
| 「看起來很乾淨，應該沒問題」 | 乾淨正是第二層 AI 味的特徵；照清單逐條對 |
| 「沒有 DESIGN.md，我憑感覺評」 | 沒有規格就沒有基準，只能評出「像不像 AI」，評不出「對不對」；先建規格 |
| 「這是使用者要的風格」 | 可以保留，但要在回報寫明是使用者指定，不是預設值 |
