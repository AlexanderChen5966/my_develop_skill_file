# 後端契約同步模式（非互動・供 hook 呼叫）

來自 requirements SKILL.md。只有被 `claude -p` 以「後端契約變更同步」為目的呼叫時才讀本檔，**不走 Step 1-8**。


當本 skill 被 **`claude -p`（headless）** 以「後端契約變更同步」為目的呼叫時，
**不走 Step 1-8**，改走本節。判斷依據：prompt 明確指定「後端契約同步模式」並附上漂移報告。

### 🔴 硬邊界（無人模式下必須自我約束）

無人模式**無法向使用者確認**，所以能改的範圍必須極小、且一眼看得出是機器寫的：

| 允許 | 禁止 |
|------|------|
| ✅ 在任務文件**末尾**新增／更新 `## ⚠️ 後端契約變更（自動同步・待確認）` 區塊 | ❌ 修改該區塊以外的**任何**既有內容 |
| ✅ 在該區塊內寫變更摘要、來源 commit、受影響章節 | ❌ 修改 `**狀態：**`／`**完成日期：**`／`**優先級：**` 等 metadata |
| ✅ 更新 `**參考文件基準：**` 的 commit hash | ❌ 改寫「實作任務」「執行步驟」——那需要判斷，留給人 |
| ✅ 新建 `docs/shared/_backend_sync_log.md` 記錄每次同步 | ❌ **新建任務文件**（要不要開新任務是人的決定）|
| | ❌ 改動 `readme.md` 索引 |
| | ❌ 執行 `git commit`／`build_runner`／任何 build 指令 |

### 步驟

1. **讀漂移報告**（由 hook 提供，或自行執行 `.claude/scripts/contract_drift_check.py`）
2. **比對 `後端依賴` 欄位**找出受影響的任務文件
   - 命中 0 份 → **只寫 log，不動任何任務文件**，結束
   - 命中多份 → 逐份處理
3. 對每份命中的文件，寫入／更新末尾區塊：

```markdown
## ⚠️ 後端契約變更（自動同步・待確認）

> 🤖 由 hook 於 YYYY-MM-DD 自動寫入，**尚未經人工確認**。
> 確認後請將相關內容整併進上方章節，並刪除本區塊。

**後端 commit：** `<old>` → `<new>`
**變更的契約項目：**
- `EntityType` 新增 `XXX`（⚠️ 前端若用非 nullable 解析 → 整批解析失敗）
- `§4.18` 回應欄位變更：...

**建議動作：** <一句話，例如「補 enum 值 + build_runner + 契約測試」>
```

4. **寫 log** 到 `docs/shared/_backend_sync_log.md`（append，含時間、commit 範圍、命中文件、未命中原因）
5. **回報**：命中幾份、改了哪些檔、有沒有「宣告缺失導致無法判斷」的文件

### ⚠️ 無 `後端依賴` 宣告的文件

**不要猜**。只在 log 記錄「以下未完成任務文件缺 `後端依賴` 宣告，本次無法判斷是否受影響」，
由使用者下次開 session 時決定。**猜錯而改到不相關的文件，比漏掉更糟。**
