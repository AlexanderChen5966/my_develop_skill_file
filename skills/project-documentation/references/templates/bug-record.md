# Bug 修復紀錄範本

此範本適用於所有技術棧的 Bug 修復紀錄。

## 標準結構

```markdown
---
title: [問題簡述]
type: bug-record
created: YYYY-MM-DD
status: completed
related-modules: [模組名稱]
---

# [問題簡述] 修復紀錄

## 問題描述

**發現日期：** YYYY-MM-DD
**影響範圍：** [哪些功能/頁面受影響]
**嚴重程度：** 高 / 中 / 低

[簡述問題現象，使用者會看到什麼錯誤]

## 錯誤現象

### 錯誤訊息
\`\`\`
[貼上完整的錯誤訊息或 stack trace]
\`\`\`

### 重現步驟
1. [步驟 1]
2. [步驟 2]
3. [觸發錯誤]

## 根因分析

**問題根因：** [一句話總結根因]

[詳細說明為什麼會發生，包含相關程式碼位置]

**問題程式碼位置：** `path/to/file:行號`

## 修復方式

### 修改內容

| 檔案 | 變更說明 |
|------|---------|
| `path/to/file.dart` | [修改了什麼] |

### 修復邏輯

[說明修復的核心邏輯，為什麼這樣改能解決問題]

## 驗證方式

- [ ] [驗證項目 1]
- [ ] [驗證項目 2]
- [ ] 確認無回歸影響

## 相關資訊

- **Commit**: [commit hash]
- **MR/PR**: [連結]
- **相關文件**: [其他參考文件]
```

## 撰寫指引

1. **根因分析是核心**：要寫清楚「為什麼會發生」，而不只是「改了什麼」
2. **保留錯誤訊息原文**：方便未來搜尋類似問題
3. **重現步驟要精確**：讓其他人能重現
4. **修改內容要列表**：一眼看出改了哪些檔案
