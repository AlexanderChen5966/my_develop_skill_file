# DESIGN.md 範本

結構對齊既有專案常見的 DESIGN.md 慣例。每段只寫專案真的會用到的內容。

```markdown
# <專案名稱> Design

## 專案定位
<一到兩句：誰用、在什麼情境用、為什麼>

## 設計原則
- <3～5 條，可驗證，例如「後台表格資訊密度優先，不留行銷頁式的大留白」>

## Colors
| Token | 值 | 用途 |
|---|---|---|
| primary | #… | 主要按鈕、連結 |
| … | | |

### 使用規則
- 主色只用在……；文字色分哪幾級；背景分哪幾層
### 系統語義色
成功／警告／錯誤／資訊各一個值與用途

## Typography
字型家族、字級階梯（名稱、字級、行高、字重、用在哪）；中文字型與備援

## Spacing
間距階梯（例：4、8、12、16、24、32）；元件內距與區塊間距各用哪幾級

## Radius
圓角階梯與各元件用哪一級

## Components
專案既有的共用元件清單與使用規則（按鈕、對話框、表格、表單欄位……）；新畫面一律用這些，不另做一套

## Icons
- 圖示庫：<名稱>；找不到再自畫
- 網格：<例 24×24>　筆畫：<例 1.5px>　端點／轉角：<圓／方>
- 風格：<線框／填色，擇一>
- 輸出：網頁 SVG；App 依平台規格輸出各尺寸 PNG
- 需要看清楚的最小尺寸：<例 16px>

## 待定
<還沒決定的項目與誰決定、何時決定>
```
