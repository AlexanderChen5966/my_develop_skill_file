# Flutter UI Compare（網頁畫面與 Flutter Web 並排量測）

Flutter Web 畫在 canvas 上，DOM 查不到文字與元素。所以兩邊用不同方法**量測**，再比數字：網頁用 DOM 量，Flutter 用截圖換算。肉眼看截圖「像不像」不算比對。

被檢查的是網頁畫面，Flutter 是對照組。

## 工具

用**使用者自己的 Chrome（Claude in Chrome 擴充功能）**做真實點擊與截圖：先載入 `claude-in-chrome` skill。Flutter canvas 上的展開、hover、tooltip、對話框，只有真實滑鼠能穩定觸發；Playwright 在 canvas 上會點不開、截到沒更新的舊畫面、`wait_for` 等不到文字。

Chrome 擴充功能連不上時停下來告訴使用者，請他重連或改提供截圖。

## 流程

照順序做，每一步達到「完成條件」才往下。

### 1. 定範圍

向使用者確認或從任務文件取得：兩邊的網址、登入的帳號與公司、要比的頁面與狀態（列表、空狀態、Drawer、對話框、窄版）。

完成條件：寫出一份「畫面清單」，每個畫面有兩邊的網址與到達步驟。**清單一定要包含頁面外框**（標題列、側選單、標誌、帳號選單），即使這次只遷移內容區：外框也會被新頁面的字型、版面設定影響（2026-11-11 推薦紀錄頁漏比外框，由使用者發現）。

### 2. 讓兩邊條件相同

- **同一筆資料**：兩邊同帳號、同公司、同篩選條件。
- **同一個視窗寬**：記下寬度寫進報告。兩個分頁可能在不同 Chrome 視窗，`resize_window` 只縮其中一個；比窄版時在**同一個分頁**先量 Flutter，再導到網頁。量完把視窗改回原寬。
- **同一套字型**：在網頁分頁用 `document.fonts` 確認 Flutter 用的字型已載入。本機 dev 沒有字型檔時，用 `new FontFace('<字型名>', 'url(<Flutter 網域的 ttf>)')` 臨時載入，並移除 error 狀態的同名 face。字型不同時文字寬度無法比較。

完成條件：帳號、公司、視窗寬、字型四項都確認相同並記錄。

### 3. 量網頁這一邊

用 `getBoundingClientRect` 量 CSS px，同時讀 `getComputedStyle` 的字級、字距、行高、顏色。

完成條件：畫面清單上每個畫面的**每個元素**都有上、下、左、右與寬高——含頁碼列、提示框按鈕、icon 這類小元素。

### 4. 量 Flutter 這一邊

1. 截圖後先求比例：截圖座標系會隨視窗與分頁變動，用一個已知尺寸的元素（原始碼寫死的表頭高、欄位寬）算出「截圖 px ÷ CSS px」，每張截圖重算。
2. 用比例把每個元素的座標換算成 CSS px。
3. 寬度、字寬這類差幾 px 就有意義的量，用 `zoom` 取該區域的原生解析度再量，兩邊取同一個 CSS 範圍並排；從縮小的截圖估寬誤差可達 10%。
4. 需要預設值時讀套件與 widget 的原始碼（例：資料表 footer 高、Card margin），以實測為準：Flutter 實際行為常與照原始碼推的不同。

完成條件：第 3 步量過的每個元素，Flutter 這邊都有對應的數字。

### 5. 比互動狀態

每個可點的元件比三種狀態：**hover、停用、tooltip**（位置、內距、有沒有出現）。再比展開的選單與對話框。

完成條件：每個可點元件的三種狀態都有「兩邊一致／不一致＋數字」。

### 6. 比資料內容

抓一批真實的後端回應看結構，再逐欄比兩邊顯示的文字。Flutter 程式讀的欄位可能不存在而一直顯示預設值，所以以實際資料為準，Flutter 畫面有錯時回報「Flutter 既有問題」，由使用者決定網頁要不要照做。

完成條件：每個欄位的顯示文字與格式（日期、數字、空值）都比過。

### 7. 判讀差異

差異超過 1px 的，先查 [`KNOWN-CAUSES.md`](KNOWN-CAUSES.md)：文字寬差 3～5%、固定高度變高、文字左距不同、行高不同這幾類都有已知原因與驗算方式。查不到原因的照實列為「原因未明」。

完成條件：每一筆差異都標上原因（已知原因／原因未明）與建議（要修／誤差內／由使用者決定）。

### 8. 回報

輸出一份對照表給使用者，遷移任務有文件時寫進該任務文件：

```
比對條件：視窗寬、帳號與公司、字型、日期
| 畫面 | 元素 | 量測項 | Flutter | 網頁 | 差 | 原因 | 建議 |
一致的區塊：（列名稱與關鍵數字）
殘留差異：（每筆附原因與建議）
沒驗到：（項目與原因）
```

修改由使用者決定後才動手；修完重跑第 3～7 步受影響的元素。動到共用元件或全站樣式時，已遷移的其他頁面也要重比。

## 收尾

- 把視窗寬改回原值。
- 測試時寫進 localStorage 的值、切換過的公司，還原成測試前的狀態。
- 這次發現的新原因，提議補進 `KNOWN-CAUSES.md`，使用者同意才寫。
